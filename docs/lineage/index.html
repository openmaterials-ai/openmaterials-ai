Lineage tour

The lineage of a shared experiment

The map derives ThermalConductivity[transport_model=qhgk] through typed edges, a lineage record pins the run that produced one value of it, and each part has its own URL. The graph below is the map's own export from python -m omai.mermaid, shown verbatim.

1 · The derivation

Read top to bottom: sources, the DFT chain, harmonic quantities, scattering channels, and transport. Observable nodes carry no gauge freedom. Hidden nodes depend on a gauge choice: the eigenvectors, group velocities, and linewidths are intermediates, and the QHGK thermal conductivity at the right end is an approximation. The dashed edge illustrates a learned shortcut: a surrogate model that produces the same linewidth node without computing the third-order force constants. The map declares no learned edge yet, so the tracer does not show one. The same derivation is live in the tracer.

Observable Hidden (gauge-dependent) Learned shortcut (illustration)

This screen is too narrow for the diagram; the tracer link above opens the same derivation.

To reproduce this graph wherever Mermaid renders, run python -m omai.mermaid "ThermalConductivity[transport_model=qhgk]" (output in the appendix). With the learned edge in place, the third-order force constants and the edge that produces them would be skipped at inference.

2 · The lineage record

The map stores the quantity and its value; the lineage record pins how the number was made and where the bulk data lives. This is the example docs/examples/a-si-kappa-qhgk.json, rendered as the playground's Lineage tab renders it. Raw artifacts never enter the store: the record carries pointers, and the files stay with their provider.

3 · The share surfaces

Each part has its own URL and audience. The public links carry the values and their provenance; the provider link carries the bulk artifacts and reruns, behind the provider's access control.

The run at its provider
the run specification, stages, artifacts, and reruns		 app.materialscodegraph.com/runs/a-si-qhgk (MaterialsCodeGraph account required) provider account

Any source works the same way: commit values under one source.ref and both public links exist; keep the bulk data at any provider and point the record's mirror at it. Unpublished work stays with the provider until its owner publishes the values.
