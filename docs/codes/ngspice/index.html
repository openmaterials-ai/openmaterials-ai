What ngspice is

ngspice is the open-source circuit simulator descended from Berkeley SPICE 3f5, with XSPICE mixed-signal extensions. It solves DC, AC and transient analyses of circuits built from device models and behavioral sources, so a device characterized on the map can be placed in a circuit and simulated at the circuit level. On the map it serves the quantities read back from its operating-point (.op) analyses.

In more detail

Lineage and scope

ngspice merges Spice3f5, Cider1b1, which couples the circuit solver to a device simulator, and Xspice, which adds code modeling and event-driven digital simulation (ngspice README). Spice3f5 is the last Berkeley release of Spice3, and XSPICE came from Georgia Tech (ngspice manual 47). Most of the work since has been bug fixing and refactoring (ngspice manual 47). The project aims at compatibility. PSPICE and LTSPICE model parameters and netlists run, and ngspice reads HSPICE device libraries from foundry PDKs for integrated circuits (ngspice home page). Input is a netlist file or the command line, output is plots or data files, and there is no schematic entry (ngspice home page).

Analyses and numerics

Analog simulation solves Kirchhoff's laws as a matrix of simultaneous equations at time steps chosen for convergence and integration accuracy, with gmin stepping and source stepping as convergence aids for the DC solution (ngspice manual 47). Since version 42 ngspice has two solvers. Sparse 1.3, which has served all simulation tasks and suits behavioral models, sits next to KLU for large transistor circuits (ngspice manual 47). OpenMP parallelizes the device evaluation inside BSIM3 3.3.0 and 3.2.4, BSIM4 4.5, 4.6.5, 4.7 and 4.8, B4SOI 4.4 and OSDI models, where about two thirds of the CPU time goes for transistor-heavy circuits. The matrix solution stays serial (ngspice manual 47).

Device models and extensions

Compact models come from the built-in set and from Verilog-A. OSDI is a simulator-independent model interface, in ngspice since release 39, and OpenVAF compiles Verilog-AMS LRM 2.x models such as BSIMBULK, BSIMCMG, PSP, HiSIM and HICUM into .osdi shared libraries loaded with the osdi command on Linux and Windows (ngspice manual 47). CIDER solves Poisson's equation and the electron and hole continuity equations in one or two dimensions for the critical devices, with PISCES-like structure input and temperature dependence from -50 to 150 degC (ngspice manual 47). XSPICE adds User-Defined Node types that carry arbitrary data. The digital state with strength is one of them (ngspice manual 47).

Interfaces

Input files may carry scripts in the control language, and wrdata writes scale and value vector pairs as ASCII with numdgt significant digits (ngspice manual 47). As a shared library ngspice exports control functions and callbacks, so a host can start a run in a separate thread, read each time point, alter device or model parameters and resume. EXTERNAL sources let the host set node values during the run (ngspice manual 47). Bindings exist for C++ (KiCad), Python (PySpice), Ruby, Octave, Fortran, Rust and Go (ngspice shared page). Digital Verilog modules compiled with Verilator or Icarus Verilog can be attached, and C processes can be reached through pipes (ngspice manual 47).
