A versioned map of physics.

OpenMaterials is a typed graph of physical quantities and the formulas that relate them. Representations of 34 codes and workflows connect their outputs to its nodes, and values from simulations and measurements attach to those nodes with their provenance and a content hash.

Where it fits

Materials Project, AFLOW, and JARVIS
Each publishes a database of computed materials properties. You can contribute a value from any of them, with its source, when its quantity is on the map and the database's license permits it.
NOMAD
A repository of uploaded calculations and experiments, with their files. The map stores no raw files, and a record can point to wherever their owners keep them.
OPTIMADE
A standard API for querying structures across materials databases. OpenMaterials publishes the typed quantities that values attach to, with their formulas, as JSON files.

The map

Quantities
136 (122 observable, 11 hidden, 3 parameter)

307 (265 formula, 42 parameter)

133

18

Each quantity is a typed node. An observable carries no gauge freedom, so codes given the same inputs should agree on it. A hidden quantity depends on a gauge choice (an eigenvector phase, or the basis inside a degenerate subspace). It is an intermediate, like the eigenvectors, or an approximation, like the RTA thermal conductivity, and codes can differ on it. An operator computes a quantity from its inputs: formula links carry its symbolic formula, and parameter links supply inputs such as the cell volume. The nodes are grouped into tiers, such as Sources, Harmonic, Transport, Ground state, and Thermochemistry.

A code representation records how one code's outputs map onto these nodes, with units and conventions. Representations exist for kALDo, phono3py, ShengBTE, LAMMPS, GPUMD, Quantum ESPRESSO, VASP, and the other codes on the codes page, each with its own page.

Values

Values attach to nodes without changing the graph. A value is a small record: the node, the material, the conditions, the number with its units, and the source. Its id is the SHA-256 hash of the record's lineage object, so the same claim always gets the same id. When values from different methods or codes answer the same question, the agreement page reports their spread. Values come from published papers and from runs of kALDo, phono3py, Quantum ESPRESSO, MESKAL (formerly MESCAL) and xtb.

Seed set: 93 values, 87 from simulations (mostly the maintainers' papers and example runs), 6 measurements.

Protocol

Every node, formula link, and value has a content hash. A change to the graph is appended to the map's change log after the gates check identity, connectivity, duplicates, and the dimensions of each formula whose symbols are registered, and after a maintainer reviews it. The map version hashes the head of that log together with the record-format rules, so citing a version pins both.

Contribute a value

  1. 01Write the file by hand, or call omai.map_data.record_instance, which writes it and computes the id.
  2. 02Add it under docs/data/instances/ and open a pull request.
  3. 03Automated checks confirm that the node exists on the map and that the id recomputes from the lineage, and a maintainer reviews the source. The map version does not change.

The playground's Learn tab exports the values you accept from a paper as JSON.

Governance

OpenMaterials is stewarded by OpenMaterials-AI, a foundation in formation. The initiative holds the map, the protocol, and the openmaterials.ai name, and changes them only through the gated contribution process. The rules are public in GOVERNANCE.md.

Decision making
A small set of scientific authors reviews changes behind the gates. GOVERNANCE.md names the next step once external contributors arrive: a technical steering group drawn from contributing groups.
Licenses
Map data is CC BY 4.0 and code is Apache 2.0.
Contributions
Contributors grant OpenMaterials-AI a non-exclusive license to redistribute each record under CC BY 4.0 and keep every other right. There is no copyright assignment and no contributor license agreement.
Credit
Reuse credits the map version and, through each record's provenance, the original source.
Removal
A rights holder who believes a record entered in error opens an issue; the record leaves the current view of the map, and the append-only log records the retraction.
Openness
Anyone can clone the repository, rerun the gates, and rebuild the Lean proofs.
Tools
Da Vinci Labs builds the site, the map views, the tracer, the playground, the codes bibliography, the paper parser, and the codebase readers. Proposals from the parser and the readers enter the map only after the gates and a maintainer accept them.
