A versioned map of physics.

OpenMaterials is a typed graph of physical quantities and the formulas that relate them. Representations of 31 codes and workflows connect their outputs to its nodes, and values from simulations and measurements attach to those nodes with their provenance and a content hash.

Each quantity is a typed node. An observable carries no gauge freedom, so codes given the same inputs should agree on it. A hidden quantity depends on a gauge choice (an eigenvector phase, or the basis inside a degenerate subspace). It is an intermediate, like the eigenvectors, or an approximation, like the RTA thermal conductivity, and codes can differ on it. An operator computes a quantity from its inputs: formula links carry its symbolic formula, and parameter links supply inputs such as the cell volume. The nodes are grouped into tiers, such as Sources, Harmonic, Transport, Ground state, and Thermochemistry.

A code representation records how one code's outputs map onto these nodes, with units and conventions. Representations exist for kALDo, phono3py, ShengBTE, LAMMPS, GPUMD, Quantum ESPRESSO, VASP, and the other codes on the codes page.

Evidence

Values attach to nodes without changing the graph. A value is a small record: the node, the material, the conditions, the number with its units, and the source. Its id is the SHA-256 hash of the record's lineage object, so the same claim always gets the same id. When values from different methods or codes answer the same question, the agreement page reports their spread.

Protocol

Every node, formula link, and value has a content hash. A change to the graph is appended to map/log.jsonl after the gates check identity, connectivity, duplicates, and the dimensions of each formula whose symbols are registered, and after a maintainer reviews it. The map version hashes the head of that log together with the record-format rules, so citing a version pins both.

Contribute a value

A value is one JSON file under docs/data/instances/, in the shape shown here.

  1. 01Write the file by hand, or call omai.map_data.record_instance, which writes it and computes the id.
  2. 02Add it under docs/data/instances/ and open a pull request.
  3. 03CI checks that the node exists on the map and that the id recomputes from the lineage, and a maintainer reviews the source. The map version stays the same, because a value attaches to the graph without editing it.

The playground's Learn tab exports the values you accept as JSON; omai.map_data.record_instance writes each one as a file in this shape. The document's appendices cover ingesting a code and extending the DAG, including when to add a node and when to add a parameter.

Governance

OpenMaterials is stewarded by OpenMaterials-AI, a foundation in formation. The initiative holds the map, the protocol, and the openmaterials.ai name, and changes them only through the gated contribution process. The rules are public in GOVERNANCE.md.

Decision making
A small set of scientific authors reviews changes behind the gates. GOVERNANCE.md names the next step once external contributors arrive: a technical steering group drawn from contributing groups.

Removal
A rights holder who believes a record entered in error opens an issue; the record leaves the current view of the map, and the append-only log records the retraction.
