What is proven, and what is not

Tier 1 is the dimensional layer. Each exported map node has a declared dimension, a Lean definition of five rational exponents over length, time, mass, charge, and temperature. A Tier 1 theorem exists only when an edge's output dimension is the product of its input dimensions, and it states that equality; the generator skips edges whose formulas sum over modes, take ratios, or take square roots. The Lean compiler checks every theorem against physlib (Lean 4.31.0); a file that compiles with zero errors and zero sorrys is the proof.

Tier 2 holds the operator identities. The map's executable identities are stated as theorems over real numbers and checked against Mathlib. A composition theorem substitutes an upstream identity into a downstream one and proves the chained form equals the flat form; a law theorem states a single identity's formula as a well-typed real equation.

Scope: physlib's Dimension has five bases and no base for amount of substance, electric current, or luminous intensity, so map nodes whose dimension needs a mole, ampere, or candela base are omitted from the export. Extending the dimension system upstream is a later tier. The coverage counts below state exactly how much of the map this leaves in.

Limits: a node's dimension here is declared, and a theorem checks the dimensions of one edge or an algebraic identity. A theorem does not show that a formula is the right physics, that a code implements it correctly, or that a value on the map is accurate. The experiment and agreement pages carry the evidence for those questions.

Reproduce this

Lean CI status. Every pull request that touches the map or the generators recompiles the full proof against physlib in CI, with warnings promoted to errors, so that status is the live state of the claim on this page.

lean/ is a standalone lake package (library OpenMaterials) on toolchain Lean 4.31.0, depending on physlib pinned by rev in lakefile.toml. The files are generated from the live map and re-checked two ways: the Lean compiler proves them, and the Python suite re-derives every dimensional identity so a regression fails fast even without a Lean toolchain. From lean/README.md:

Rebuild the proofshell
git clone https://github.com/openmaterials-ai/openmaterials-ai.git
cd openmaterials-ai/lean

lake exe cache get   # fetch the mathlib build cache (first build only)
lake build           # compiles every generated module; zero errors, zero sorries

# the Python re-check (no Lean toolchain needed), from the repo root:
pip install -e . && python -m pytest tests/test_physlean_export.py tests/test_lean_tier2.py -q

The generated sources: OpenMaterials.lean (Tier 1 dimensions and edge theorems), OpenMaterialsIdentities.lean (Tier 2 identities), OpenMaterialsDimensions.lean (the seven-base dimensional closure), OpenMaterialsUnits.lean (the units bridge).
